# Model allocation by assignment and budget

polaris selects model and effort together by assignment kind, level, provider profile, and budget. Fixed roles combine different kinds of work under one allocation. A flat category list also mixes difficulty with activities such as verification. Separate fields let a difficult implementation use a different allocation from discovering its design.

Reasoning finds or judges an approach and has scoped, hard, and very hard levels. Execution carries out a familiar or settled approach and has regular and complex levels. Verification spans both kinds. Consequences determine safeguards and independent review separately from reasoning difficulty. An uncertain assignment uses a separate, temporary `unclassified` allocation and is reassessed after exploration.

Budgets select explicit model–effort pairs rather than monetary caps or uniform effort offsets. Fixed overrides survive budget changes. Project settings take precedence over the current harness's user settings, then bundled defaults. A task-only budget does not change saved settings or fixed overrides. Provider connections, authentication routes, model IDs, and required capabilities remain separate from assignment classification.

Delegation must already serve parallel work, independent judgment, or bulk reading. Model allocation does not justify starting a child solely to switch models or changing the parent session's model. Harnesses may require generated model-pair agent definitions to apply effort. Hermes retains its existing delegation behavior instead of gaining a separate-process workaround.

Fallbacks require explicit authorization. A profile may authorize a more expensive fallback within its budget; that does not authorize another budget's allocations. Cross-provider fallback requires a configured ordered list or the user's approval. Unsupported effort needs a documented model-specific mapping or a saved user choice. If no authorized fallback exists, pause the affected assignment and continue independent work. Report actual substitutions and preserve required capabilities and independent judgment.

Exact allocations, configuration syntax, and harness application rules live in [model budgets and profile references](../../skills/polaris/references/models.md). They are selected policies to evaluate, not measured equivalence or savings claims. [Verification evidence](../model-budget-verification.md) distinguishes configuration checks, accepted requests, successful execution, and cost comparisons.
